# 电源与合盖

Mac 睡眠时不能承担持续转发。作为固定网关使用时保持接电，并在本机读取当前设置：

```sh
/usr/bin/pmset -g
/usr/bin/pmset -g custom
/usr/bin/pmset -g assertions
/usr/bin/pmset -g batt
```

禁止闲置睡眠不等于合盖一定保持运行，进程常驻也不等于硬件保持唤醒。项目安装器不改电源设置，不默认设置全局 SleepDisabled。

`pmset -g` 的 `SleepDisabled=1` 是全局禁睡状态，不应解读为仅接电生效。`custom` 中的接电和电池闲置睡眠时间不能证明全局禁睡已经按供电收窄。已有部署依赖该设置通过合盖测试时，直接清零会改变已验证的运行条件。

从 `0.1.0-alpha.5` 开始，诊断报告将供电来源、睡眠策略、当前盖状态和下游协商速率分别解释；电池供电且全局禁睡记为 attention，命令失败、矛盾或无法识别的结果记为 unknown。当前盖状态只是采样瞬间，报告不会从开盖状态推算之前的合盖时长。界面从报告展示相同证据，不后台修改电源。

接电防闲置断言仅适用于闲置睡眠，不构成无外接显示器合盖运行的保证。参见 [Apple 断言说明](https://developer.apple.com/documentation/iokit/kiopmassertiontypepreventuseridlesystemsleep)。目前不提供轮询全局禁睡开关的电源守护服务，也不把未验证的替代方案部署到工作网关。

若用户需要合盖，先明确其硬件、外接设备、电源条件和拟改变的设置，记录原值，再在可恢复窗口进行真实测试。让连接下游路由器的客户端关闭备用网络，合盖约一分钟，访问预定站点，并记录接口、进程和转发状态；失败时开盖恢复。

一次短测通过只证明该配置在该时间段可用。跨夜、电源切换、系统更新和重启需要分别验证，不能把专用部署的短测推广到所有 Mac。通用包不承诺任意 Mac 的闭盖支持。

诊断报告包含可手工补充的合盖验收记录：起止时间、持续接电情况、真实下游设备、备用出口是否关闭及实际结果。空白记录不是已通过；JSON 中的 `downstream_verified=false` 仍表示采集器没有独立验证下游。

任何后续电源模块都应默认关闭，只恢复自己拥有且未被第三方修改的值，并保存原值与恢复状态。原值已经为一时，拔电后改成零是新策略，不能描述为恢复原值。
