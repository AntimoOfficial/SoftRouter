# SoftRouter 网络巡检

读取仓库中的 `softrouter/docs/diagnostics.md`，使用 `softrouter/diagnose.sh`；新安装的网关也可用 `/Library/SoftRouter/gatewayctl diagnose`。无需安装 Skill 专用依赖。Skill 文件被复制到其他目录后，先定位用户的 SoftRouter 仓库或已安装入口，不假设相对路径仍可用。命令不存在时明确缺少该版本，不编造接口。

先确定本机实际部署与用户要看的时间范围。保持现网，使用非特权入口；旧部署可以显式传 --label 与 --log-dir。核对后填写接口，不套用学校 IP、主机名、MAC、网卡编号或历史个人路径。

按请求选取至多五个真实公开入口，传 --url；已知本机 HTTP 代理且需比较时传 --proxy。网站登录页可以只读检查，不提交登录。不要把密码、订阅 URL、带凭据或查询参数的链接放进命令。没有网站目标时，报告明确只验证本机状态。

运行后读取 report.json 与 report.md。关注下列易误判处：

- 磁盘 RUNNING 要与启动会话、launchd PID、守护/转发进程及转发开关交叉核对；状态更新时间不是心跳。
- observed 表示取得结果，不是全网健康；unknown、超时、空日志和缺少权限不能变成正常。
- 进程持续运行不等于互联网持续在线；网卡错误计数不等于丢包率；不凭快照计算在线率。
- 历史漫游、EAP 成功与 DHCP BOUND 可以支持自动恢复，但事件间隔不是实测中断时长，也不证明认证失败根因已解决。
- HTTP 200 可能是错误页。对用户实际故障核对正确路径与公开内容；程序没有验收登录与全部子资源。
- 本机代理不自动覆盖路由器下游。需要下游证据时询问真实客户端结果，排除蜂窝兜底；无权限或用户暂停的设备保持未验证。

报告应给出明确时间窗、当前状态、历史事件及尚未验证项，附本地报告链接。补充检查只针对未解决的问题，限制耗时，不重复跑全库日志统计。任何网络修复都不属于本 Skill 的默认行为；用户明确要求修复后再按实际授权处理。报告保留本地，分享前脱敏，不自动上传或修改开源仓库。
