# 测试与验收

## 已有证据的适用范围

专用配置在 macOS 14.8.5、Apple M1 和一款 USB 以太网适配器上曾完成真实客户端网页访问，并观察到双向 DNS、HTTPS 与 NAT 连接状态。相关行为修复还经过离线替代函数测试。

这些结果属于通用化之前的专用部署。本仓库尚未进行真实安装验收，不能将原部署的成功推广到任意 Mac、网卡、macOS 版本或企业认证环境。本仓库不包含原部署的配置与运行日志。

## 不接管网络的检查

在仓库根目录运行 `/bin/bash air-gateway/tests/run.sh`。它检查 Bash 语法、配置解析、选定守护函数和发布边界；macOS 上另检查 launchd 模板。开发检查需要 Python 3，实际网关不依赖 Python。

守护回归从实际源码提取函数，并把 PF、网卡、ND6、路由和上游查询替换为命令替身，覆盖 DHCP 规则顺序/范围及保护规则、IPv6 未初始化和禁用读回、未知 PF 子锚拒绝、上游消失/恢复只更新观测。发布测试覆盖私有文件误暂存、密钥模式和符号链接拒绝。没有加载真实 PF 或操作真实网络，也不模拟完整的包转发语义、进程竞态或断电。

从仓库根目录运行 Shell 语法检查：

```sh
/bin/bash -n install.sh
/bin/bash -n gateway.sh
/bin/bash -n gatewayctl
```

语法检查不会验证 PF 规则语义、管理员权限、配置值或实际网络行为。PF 只解析检查也不等同于真实规则加载与转发测试。离线测试应使用替代命令与临时目录，不得通过更改当前 Wi-Fi、路由或 PF 来模拟失败。

## 首次联网验收

1. 按 README 识别独立下游网卡，核对 UUID、MAC、服务配置及子网没有冲突；记录安装前默认出口和本机网络状态。
2. 安装并检查 `gatewayctl status`，确认 `RUNNING`。此状态只说明网关资源建立成功。
3. 配置路由器 WAN 地址、网关、掩码和 DNS，再接入 WAN 网线。路由器 LAN 必须使用不同子网。
4. 客户端只保留到该路由器的连接，关闭蜂窝数据、其他热点与 VPN。确认客户端的默认网关属于路由器 LAN，再访问一个未缓存的 HTTPS 页面。
5. 结合客户端结果与 Air Gateway 的 PF 连接状态确认路径。Air 自己能打开网页，或者浏览器通过代理访问成功，都不能单独证明路由转发正常。
6. 执行正常停止，确认 `STOPPED`、`cleanup_ok=1`，随后确认再次启动可通过预检。本机原来的 Wi-Fi、默认出口、DNS 与代理不应由项目改写。

PF 状态检查通常需要管理员权限，并可能包含通信端点信息；只在本机查看，不将完整输出提交到公开问题。

## 故障情形

以下涉及中断网络的项目应在可接受停机、有本地终端访问的环境中人工验收；不能把离线模拟通过标成实际测试通过。

| 情形 | 预期结果 |
|---|---|
| 启动时 Wi-Fi 无地址或无默认路由 | 服务仍可建立本轮配置，上游仅报告不可用 |
| 上游短暂断开，随后恢复 | 不因健康观测退出或撤销转发；恢复后新连接可用 |
| 默认路由改到其他接口 | 下游转发不会从其他出口放行；项目不改回默认路由 |
| 同一上游接口切换 SSID | 共享可跟随新网络，不能解释为 SSID 隔离 |
| 下游接口没有初始化 IPv6 | 不发 IPv6 配置命令，运行检查接受明确的未初始化状态 |
| IPv6 禁用命令报错但退出码为零 | 读回检查应拒绝将其当作设置成功 |
| 已有 PF 使用者或不兼容规则 | 预检拒绝接管，不清空对方资源 |
| 正常停止与再次启动 | 本轮资源清理完成，自身空规则锚不阻止再次启动 |
| 同次启动中存在不明遗留状态 | 显示 `ATTENTION`，不删除状态锁强行重启 |
| 睡眠、网卡移除、系统重启 | 不能承诺持续联网；恢复后重新核对接口与资源状态 |

持续运行验收须同时记录系统版本、硬件类型、持续时间和实际执行的故障项目。没有发生故障只能描述观测期间的结果，不能证明无限期稳定或排除内核崩溃。
