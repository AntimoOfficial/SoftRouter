# DNS 与客户端代理

校园域名可能在校内外解析成不同地址。Mac 本机能打开、下游不能打开时，应对比两边实际 DNS 结果，不能仅凭其他网站可用就排除解析问题。

在上游 Mac 本地查看当前 DNS。将接口替换为已经核对的 Wi-Fi 接口：

```sh
/usr/sbin/ipconfig getoption en0 domain_name_server
/usr/sbin/scutil --dns
```

在下游设备分别查询路由器 DNS 与上游 DNS，对比同一个实际故障域名。不要固定使用示例域名或曾经某台机器取得的 DNS 地址。检查 TCP/TLS、HTTP 结果和实际页面；若需要用 curl --resolve 对比，保留原域名及 TLS 校验，仅临时指定目的地址。

路由器静态 WAN 的 DNS 应使用在当前上游有效的解析器。在一个专用部署中，公共 DNS 给出可建立 TLS 但 HTTP 内容超时的地址，校园 DNS 给出可正常访问的地址；调整路由器 DNS 后恢复，个别客户端约一分钟后随旧缓存失效恢复。这个现象不能作为任何环境下的固定等待时间。

客户端启用 Clash/Mihomo 时，分别验证直连与实际代理路径。需要校园域名直连时，把对应后缀规则放在覆盖它的通用规则之前，并使用能得到正确校内结果的解析器。配置文件保存后，核查实际运行核心的规则和查询结果；不能把保存文件等同于配置生效。

本项目不会默认修改代理订阅。任何扩展应与订阅正文分开，并针对当前客户端版本核对格式和接口。控制器认证信息只能在本机使用，不输出到诊断或提交到仓库。

路由器使用上游 DNS 能覆盖多数普通客户端，但浏览器自有加密 DNS、代理的独立 DNS 或旧缓存仍可能产生不同结果。不能假定改完一个位置就修复所有解析路径。可移动笔记本的系统 DNS 不应因一次固定网关排障就永久绑到某个校园解析器。
